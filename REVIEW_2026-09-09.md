# Reliability review — 2026-09-09

## Scope

Reviewed hosted chat and embedding gateways, browser embedding ingestion,
blob access/downloads, upload recovery, the current upload workflow, and
development/release configuration. This is a focused reliability pass, not
an exhaustive security audit or a product redesign. No dependency upgrades,
on-chain writes, live model calls, or Vercel deployment are part of this change.

## Corrections

| Finding | Result |
| --- | --- |
| A failed fallback request was caught by the primary request's catch block and could trigger a second fallback. | One fallback at most, a shared 45-second request deadline, and cancellation of the discarded primary response. |
| Embedding ingestion accepted wrong dimensions, non-numeric values, and zero vectors; squaring large finite values could overflow. | One shared vector validator for browser and server: 768 finite components, nonzero finite magnitude, stable normalization. Invalid batches never return a successful partial result. |
| Missing access decisions or unsupported on-chain policy objects could reach a permissive branch. | Unknown policy objects fail closed. Allowlist and purchase policies need a boolean decision; known elapsed timelock behavior is preserved. |
| Cancelling a pending stream read could look like a successful end of stream. | Check cancellation after reads and before publishing the blob; release the reader and cancel oversized response bodies. |
| Download length checks compared decoded bytes against compressed Content-Length. | Retain decoded-byte limits and uncompressed truncation checks without rejecting a decoded response just for differing compressed length. |
| Upload journal records were structurally validated without checking their embedded wallet/network against the requested workspace. | Discard mismatched records before recovery can reuse their UID. |
| Local setup instructions did not match the current Vite API middleware or the fullstack script's env-file path. | Correct the README and describe the bounded gateway behavior. |

No storage schema changes are required. Valid existing vectors and upload
records remain usable. Previously malformed vectors already stored in an
index are not migrated; rebuilding that index obtains validated vectors.

## Verification boundaries

Regression tests cover the findings above. The repository preflight also
checks types, lint, unit tests, the retrieval benchmark, production build,
browser workflows, and production dependency advisories.

Final preflight passed: lint, both TypeScript projects, 405 unit tests
(1 real-PDF test skipped), 79 retrieval benchmark cases (also included in
the unit suite), production build, and 28 browser tests (1 real-PDF test
skipped). Dependency audit reported 0 critical, 0 high, and 8 moderate
findings. The initial browser run failed because symlinked dependencies
were outside Vite's allowed filesystem; rerunning with a local dependency
copy passed without changing the application's filesystem policy.

Browser wallet/provider fixtures demonstrate application behavior, not live
Shelby durability or real model answer quality. The real-PDF tests require
`SHELBY_REAL_PDF_URL`; the live 30-question provider benchmark remains opt-in.

## Remaining concerns

- The wallet dependency chunk remains about 5.2 MB raw / 1.3 MB gzip. It is
  loaded on demand; a bundle reduction needs separate dependency analysis.
- Gateway origin checks are not authentication. In-memory rate limits are
  per process and cannot enforce a global spending budget across serverless
  instances. Public paid usage needs an explicit quota/authentication design.
- The AI deadline is per gateway request. A multi-step agent turn can still
  make several requests; a whole-turn budget is a separate behavior change.
- Expiration/network availability and current provider model availability
  still need live verification before a future production release.
